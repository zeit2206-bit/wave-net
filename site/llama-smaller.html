What we did

Rounded to 4 bits, watching sentences. Each weight was rounded in turn, and the others were nudged so each layer's output stayed close to the original's. Layers were done in order, floor by floor. ~15 minutes.

Wrote a new model file in the standard 4-bit format. Only the 112 layer matrices changed; the word table and the rest were copied. Ollama's original file was only read.

Checked the file by loading it back in our own code: same score as before saving (10.47).

Added it to Ollama (with your OK) as llama3.2-1b-gptq-q4, using the original's chat format.

Why it's faster, not just smaller

To write each word, the model reads all its weights from memory. That reading, not the math, is the slow part. Half the bits means half the reading, like carrying a lighter backpack up the same stairs: about 1.6× more words per second.

Keep in mind
  • Quality was checked on one text and two prompts. Longer use could show small differences.
  • Ollama's own ready-made 4-bit versions use similar tricks; ours is not claimed to beat them, but we built it ourselves and know exactly what's inside.
  • Use it: ollama run llama3.2-1b-gptq-q4. Remove it: ollama rm llama3.2-1b-gptq-q4.
  • The same file could run in an Android app via llama.cpp (~1 GB memory).
