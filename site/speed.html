Why they were slow at first

Think of moving 64 coins across a room.

  • My first gate code carried each coin in its own big box, one trip per coin: each bit was stored in a whole byte, with Python loops on top.
  • The standard network used NumPy's matrix library: a forklift tuned for decades.

The race said nothing about which job is lighter. It compared a forklift with carrying boxes by hand.

Fix 1 · Pack 64 images into one number

A CPU works on 64-bit numbers. One AND between two of them does 64 ANDs at once. So we stored the same bit for 64 different images in one number. One operation = one gate for 64 images.

Fix 2 · Compile to machine code

NumPy creates many temporary copies for this kind of work. We installed Numba (with your OK), which turns the Python into real machine code that runs on all 16 CPU threads.

Keep in mind

The standard network wasn't specially tuned either. A gate (one AND on 64 images) is a much simpler job than a multiply-add, but the standard network has decades of library tuning behind it. Fairness gets checked properly in step 8.
